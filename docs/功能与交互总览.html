旅行 × 生活决策助手

核心不是「帮你做行程」，而是帮你做决定。产品围绕 想 → 选 → 去 三段组织：先用一句话接住模糊的念头， 再给出少量可比较的候选，最后才落到可执行的时间线与地图。 刻意不做「一上来就生成 7 天完整行程」——那是计划，不是决策。

Architecture

架构分层

决策层负责「想」和「选」，执行层负责「去」。两层通过 PlaceState / WeekendPlan / Trip 数据贯通，但 UI 上刻意分开——周末不应该是旅行的缩小版。

决策层 · 想 → 选

输出「少量候选 + 为什么」，不生成行程

Decision Layer

决策层页面与交互

本阶段重点改造区域。所有页面都支持从首页输入框一句话直达。

页面交互状态
/ 首页 ① 当前计划（有旅行才显示，不占位）② 周末常驻区块 ③「现在想做什么」输入框 ④ 其他旅行 / 新用户兜底入口 三段式，不堆功能
/discover 两级：先选「旅游 / 周末安排」，再进对应决策流。 带 ?q= 且场景模糊时走 ClarifyFlow 澄清 （旅游 / 周末 / 换个说法） 有明确返回路径
/discover/travel 4 个入口：不知道去哪 → quiz、有几个备选 → compare、随便抽 → random、已决定 → 新建
/discover/weekend 周末决策入口：去哪玩 / 做什么
/weekend 4 种模式（去哪玩 / 做什么 / 附近看看 / 从收藏中选）→ 真实高德 POI → 最多 3 个候选卡；选中后「直接去 / 加入计划 / 帮我安排一下」； 有计划时显示清单 + 查看完整安排 默认轻量
/quiz 9 问测评；?q= 预填出发地与范围 + 上下文提示条 已明确目的地时不再进此页
/destinations 3 个推荐结果；?q= 按名称 / 国家 / 省份 / 标签过滤 承接「想去日本」类输入
/destinations/:id 目的地详情 + 真实高德天气条（国内）+ POI 加入行程池 海外无天气 → 优雅隐藏
/compare ?q= 自动挑出候选并排对比：分数 / 预算 / 天数 / 交通 / 优缺点
/random ?q= 预置抽签范围（国内 / 海外 / 某国），不想答题直接抽
/trips/new ?q= 解析目的地预填，四个字段即可创建

Global

全局能力

跨页面生效的基础交互与入口设计。

一级导航

发现 / 首页 / 周末 / 行程 / 地图 / 预算 / 更多。移动端底部 6 格。周末与旅行「行程」平级。

周末入口智能跳转

这周末有计划 → 直达 /weekend/plan（执行层 + 地图）；还没计划 → 进 /weekend（决策层）。

一句话意图路由

输入框不要求先选场景，关键词识别后直接跳到对应页面并触发候选生成，不调用 LLM，零延迟。

语音输入

Web Speech API 实时回填文本；不支持的浏览器给出提示而非报错——语音只是输入方式，不是壁垒。

ContextHint 上下文提示

目标页顶部显示「系统听懂了什么」，并提供「换个说法」，避免黑盒跳转。

ClarifyFlow 澄清

意图模糊时给出「旅游 / 周末安排 / 换个说法」三个出口，带着原始输入继续走。

帮我安排一下

按地点类型建议出发时间、按距离建议交通方式，展开「出发 / 路上 / 停留」三栏 + 高德路线规划入口。

真实天气（AMap）

后端聚合高德 regeo → 天气预报，映射为结构化数据；未配置 Key 或海外目的地时优雅降级为空。

Known Issues

已知问题与后续

  • favicon.ico 404 —— public/ 目录为空，未放入图标。无功能影响。
  • Journey 照片数显示为 0 —— MockMap 中 photoCount 为硬编码，非本轮引入。
  • 高德 POI 偶发 502 —— QPS 限流导致。已加 150ms 节流 + 早停 + 单次重试，页面不白屏。
  • 高德天气仅覆盖国内 —— 海外目的地返回 INVALID_PARAMS，天气条自动隐藏，属预期行为。
  • React Router v7 future flag 警告 —— 仅控制台提示，无功能影响。

后续候选

  • 多轮对话式 ClarifyFlow —— 目前是澄清入口，尚未做成多轮对话。
  • 「生活即时」场景 —— 架构方案中的第三场景（此刻 / 附近）尚未展开。
  • 周末计划与旅行行程的互通 —— 目前两条执行链互相独立。
